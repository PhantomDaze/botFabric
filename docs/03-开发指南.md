## 2. 插件清单

```yaml
id: example.reply
name: Example Reply
version: 0.1.0
runtime: in_process
entry: builtin.reply

provides:
  services: []
  subscriptions: [bot.message.group]

requires:
  services: [botfabric.response]
  permissions: [event.read.message, action.send_message]

limits:
  timeout: 2s
  memory: ""
```

插件只能注册清单声明的服务和订阅。Manifest 可选声明路由规则：

```yaml
routing:
  dedup:
    enabled: true
    strategy: auto
    window: 2s
    duplicate_mode: forward
  rules:
    - id: help
      priority: 100
      match:
        topic: bot.message.group
        text_regex: '^/help(?:\s|$)'
      action:
        mode: selective
        targets: [example.reply]
        response:
          mode: first_wins
          timeout: 3s
```

## 3. 公共契约

### 3.1 EventBus 与 ServiceGateway

```go
type EventBus interface {
    Publish(ctx context.Context, event Event) error
    Subscribe(topic string, handler EventHandler, opts ...SubOption) (Subscription, error)
}

type ServiceGateway interface {
    Invoke(ctx context.Context, req Request) (Response, error)
    Register(service ServiceDescriptor, handler ServiceHandler) error
    Unregister(serviceID string) error
}
```

事件广播和服务调用是两个独立模型，不再使用把 Publish/Subscribe 隐含在统一网关中的旧接口。

### 3.2 Event 与消息

`Event` 至少包含 `ID`、`Topic`、`Schema`、`Timestamp`、`Source`、`BotID`、`EndpointID`、`TraceID`、`Payload`。路由仲裁时还会附带 `RequiredReplyBot` 和 `ResponsePolicy`。

`GroupMessage`、`SendMessageRequest` 的 QQ ID 使用字符串。发送请求支持 `BotID`、`EndpointID`、`EventID` 和 `IdempotencyKey`，由中间层选择最终协议连接。

### 3.3 Endpoint

```go
type EndpointInfo struct {
    ID, Owner       string
    Kind            EndpointKind // protocol / application
    Protocol        string
    Version         string
    BotID           string
    ConnectionID    string
    Capabilities    []string
}
```

协议端在连接收到 self_id 后注册端点；应用端连接建立时注册端点。端点信息不应由业务载荷伪造。

## 4. 路由与去重

默认情况下，标准事件广播给所有匹配 Topic 的进程内订阅者和应用端 sink。路由插件可以根据 Topic、Schema、BotID、群号、用户号、Header 和文本正则选择目标。

支持的动作：

- `broadcast`：全部候选；
- `selective`：指定 Targets；
- `drop`：丢弃；
- priority 降序匹配；
- fallback 规则；
- `RouteClassifier`：可由 mock 或后续真实 LLM 实现。

去重支持：

- `message_id`：优先使用协议消息 ID；
- `fingerprint`：群号、用户号和规范化文本；
- `auto`：有消息 ID 用消息 ID，否则用指纹；
- `drop` 或 `forward`；
- `Store` 接口提供进程内存与 Redis 两种实现；启用 Redis 时去重状态跨实例共享，`SET NX EX` 原子首占、TTL 自动过期；未启用时回退内存。

## 5. CandidateReply 与响应仲裁

应用端不应直接调用协议动作服务完成竞争回复，而应提交：

```go
type CandidateReply struct {
    EventID, ApplicationID string
    GroupID, Text          string
    TargetBotID            string
    Priority               int
    IdempotencyKey         string
}
```

调用 `botfabric.response/Submit` 后：

- `first_wins`：第一个有效候选原子获胜并发送，迟到候选丢弃；
- `priority_override`：在配置窗口内收集候选，窗口结束选择最高优先级；
- `RequiredReplyBot`：应用端不感知具体连接，中间层按 BotID 找协议端；
- `FallbackBots`：目标机器人不可用时按顺序选择备用机器人；
- 每事件最多一个 winner，幂等键避免重复发送。

响应状态存储与去重一样支持进程内存与 Redis 两种实现。Redis 实现以事件级 hash key + Lua 脚本保证 Claim/TryWin 原子，并以 key TTL 兜底进程崩溃；多实例共享后 winner 判定跨实例一致。

分布式 Store 配置（`config/runtime.example.yaml`）：

```yaml
redis:
  enabled: false # 关闭时去重与响应状态回退到进程内内存实现
  address: 127.0.0.1:6379
  password: ""
  db: 0
  key_prefix: "botfabric:" # 多实例共享 Redis 时的命名空间隔离
```

`enabled: true` 时装配路径在 `cmd/server/main.go`：连接 Redis（Ping 探活，不可用即启动失败）、创建去重与响应两个 Redis store、分别注入 `manager.SetDedupStore` 与 `coordinator.SetStore`。`key_prefix` 用于多实例共享同一 Redis 时的命名空间隔离，空值缺省为 `botfabric:`。Redis 不可用时本轮不自动降级内存——启用即要求可用，`Claim`/`TryWin` 在 Redis 出错时保守返回 false（视为已占用/已有 winner），避免重复发送。

## 6. OneBot 接入

### 6.1 协议端

`plugins/protocol/onebot` 作为 OneBot v11/v12 反向 WebSocket 服务端。协议端主动连接 BotFabric，事件转换为标准 `GroupMessage`，动作请求按 `BotID/EndpointID` 选择协议连接。

### 6.2 应用端

`internal/onebotapp` 支持三种模式：

- `server`：BotFabric 监听，应用端主动连接；
- `client`：BotFabric 主动连接应用端；
- `both`：两种方向同时启用。

应用端接收到 v11/v12 群消息事件后，可回发 `send_group_msg` 或 `send_message`。必须用 `__botfabric_event_id` 或 echo 关联原事件，适配器才会生成 CandidateReply。回复缺关联信息时，适配器按该连接同群最近一个未决事件 fallback 关联（仅按 `group_id` 过滤），使无法携带关联信息的简易应用端也能参与响应仲裁；无可用未决事件时回复失败（应用端收到 `failed`），不静默丢弃。

连接治理：

- **心跳保活**：`heartbeat_interval` > 0 时，中间层周期性发送 Ping 并以 Pong 续期读 deadline；无流量的死连接会在约 `2×heartbeat_interval` 后被检测并断开。`= 0` 保持无心跳行为（向后兼容，不推荐生产使用）。应用端实现需在读循环中处理 Ping 并回 Pong（OneBot 实现通常已具备）。
- **写超时**：`write_timeout` 作用于数据帧写，避免慢/卡死对端无限阻塞写锁。
- **client 重连**：`reconnect_interval` > 0 时，client/both 模式断线后按指数退避自动重连（上限 `reconnect_max_interval`，次数 `reconnect_max_tries`，0 表示无限）。`= 0` 保持旧行为（首次拨号失败即返回，不重连）。
- **server 身份保持**：应用端可在任一帧携带 `__botfabric_endpoint_id`（或 `self_id`）声明稳定身份；重连后以同 ID 复用端点，路由与响应状态可关联。未声明时退化为每次连接生成新 ID。
- **静默丢失修复**：事件被路由到无可用连接的应用端 sink 时，适配器返回错误使 EventBus 记死信，而非静默丢弃。

配置示例：

```yaml
application_onebot:
  enabled: true
  mode: both
  listen_address: 127.0.0.1:8091
  path_v11: /application/v11
  path_v12: /application/v12
  access_token: replace-me
  read_timeout: 10s
  write_timeout: 5s
  heartbeat_interval: 30s
  remote_address: 127.0.0.1:8092
  remote_path: /onebot
  remote_version: v11
  reconnect_interval: 2s
  reconnect_max_interval: 16s
  reconnect_max_tries: 0
```

## 7. Go SDK 与外部语言

Go 插件使用 `sdk/go`，只依赖 `pkg/contract`。SDK 提供 EventBus、ServiceGateway、JSON 编解码和超时辅助。

外部进程插件通过 Runtime 托管的 Unix Socket 双向 gRPC Session 接入。Runtime 以 `BOTFABRIC_SOCKET`、`BOTFABRIC_PLUGIN_ID`、`BOTFABRIC_PLUGIN_VERSION`、`BOTFABRIC_PROTOCOL_VERSION` 和随机 `BOTFABRIC_SESSION_TOKEN` 环境变量启动 `runtime: process` 的 `entry`，子进程首帧必须以这些身份信息完成握手；握手成功后，同一连接复用事件投递、服务调用、Health 与 Shutdown。`Provides.Services` 自动映射为 Runtime 到插件的远程服务，`Provides.Subscriptions` 自动映射为事件投递；插件向 Host 发布事件或调用服务时仍受 Manifest 和静态权限策略约束。协议生成代码位于 `gen/botfabric/v1`，跨语言 SDK 应以 `proto/botfabric/v1/process.proto` 为稳定契约。

## 8. 权限、生命周期与测试

- 默认权限策略为 deny；
- 所有调用经过可信 Caller、权限、超时、TraceID、审计；
- Stop/Unload 先停止新任务，再等待在途任务，最后清理服务、订阅、端点、路由和分类器；
- Reload 先 staging，新实例成功后原子切换，失败保留旧实例。

## 9. 当前限制

1. 外部进程 transport 已支持 Unix Socket 双向 gRPC Session；
2. LLM 目前只有接口和 mock；
3. 去重/响应 Store 支持进程内存与 Redis 共享两种实现；Redis 不可用时本轮不自动降级内存；
4. 应用端回复缺关联信息时按同群最近未决事件 fallback 关联，无未决事件时失败；建议应用端尽量显式携带 `__botfabric_event_id`/echo；
5. server 模式端点身份保持依赖应用端主动声明 `__botfabric_endpoint_id`/`self_id`，未声明时重连得新 ID；
6. Python/TypeScript SDK、高级沙箱和性能基准待后续实现。
