## 2. 插件清单

```yaml
id: example.reply
name: Example Reply
version: 0.1.0
runtime: in_process
entry: builtin.reply

provides:
  services: []
  subscriptions: [bot.message.group]

requires:
  services: [botfabric.response]
  permissions: [event.read.message, action.send_message]

limits:
  timeout: 2s
  memory: ""
```

插件只能注册清单声明的服务和订阅。Manifest 可选声明路由规则：

```yaml
routing:
  dedup:
    enabled: true
    strategy: auto
    window: 2s
    duplicate_mode: forward
  rules:
    - id: help
      priority: 100
      match:
        topic: bot.message.group
        text_regex: '^/help(?:\s|$)'
      action:
        mode: selective
        targets: [example.reply]
        response:
          mode: first_wins
          timeout: 3s
```

## 3. 公共契约

### 3.1 EventBus 与 ServiceGateway

```go
type EventBus interface {
    Publish(ctx context.Context, event Event) error
    Subscribe(topic string, handler EventHandler, opts ...SubOption) (Subscription, error)
}

type ServiceGateway interface {
    Invoke(ctx context.Context, req Request) (Response, error)
    Register(service ServiceDescriptor, handler ServiceHandler) error
    Unregister(serviceID string) error
}
```

事件广播和服务调用是两个独立模型，不再使用把 Publish/Subscribe 隐含在统一网关中的旧接口。

### 3.2 Event 与消息

`Event` 至少包含 `ID`、`Topic`、`Schema`、`Timestamp`、`Source`、`BotID`、`EndpointID`、`TraceID`、`Payload`。路由仲裁时还会附带 `RequiredReplyBot` 和 `ResponsePolicy`。

`GroupMessage`、`SendMessageRequest` 的 QQ ID 使用字符串。发送请求支持 `BotID`、`EndpointID`、`EventID` 和 `IdempotencyKey`，由中间层选择最终协议连接。

### 3.3 Endpoint

```go
type EndpointInfo struct {
    ID, Owner       string
    Kind            EndpointKind // protocol / application
    Protocol        string
    Version         string
    BotID           string
    ConnectionID    string
    Capabilities    []string
}
```

协议端在连接收到 self_id 后注册端点；应用端连接建立时注册端点。端点信息不应由业务载荷伪造。

## 4. 路由与去重

默认情况下，标准事件广播给所有匹配 Topic 的进程内订阅者和应用端 sink。路由插件可以根据 Topic、Schema、BotID、群号、用户号、Header 和文本正则选择目标。

支持的动作：

- `broadcast`：全部候选；
- `selective`：指定 Targets；
- `drop`：丢弃；
- priority 降序匹配；
- fallback 规则；
- `RouteClassifier`：提供 mock 与真实模型实现。真实模型适配 OpenAI Chat Completions、Anthropic Messages、OpenAI Responses 和 Google Gemini `generateContent`；可选真实分类器 ID 为 `classifier.real-llm`，须显式加载。协议请求失败、输出解析失败或计划无效时回退广播；

### 可选真实 LLM 分类器

将 `classifier.real-llm` 内置 manifest 加入 Runtime 扫描目录即可启用；默认配置不会加载该插件或请求模型。Runtime 会扫描目录内所有 YAML，加载前请检查目录内容。清单中的路由规则必须与内置 manifest 完全一致，否则 loader 会拒绝加载。

通过 `BOTFABRIC_CLASSIFIER_REAL_LLM_FORMAT` 选择 API 格式；缺省为 `openai_chat_completions`，并兼容旧配置。Endpoint 必须指向所选协议的 API root 或完整请求 URL；Gemini 的 model ID 位于 URL 路径，可配置 API root（例如 `https://generativelanguage.googleapis.com/v1beta`），分类器会拼接 `models/{model}:generateContent`，也可直接提供完整 generateContent URL。当前格式标识如下：

| 格式 | 请求/响应协议 | 认证头 | JSON 输出约束 | 本地 stub 契约 | 真实端点/模型验证 |
|---|---|---|---|---|---|
| `openai_chat_completions` | `POST` 完整 Chat Completions URL；解析 `choices[0].message.content` | `Authorization: Bearer` | `response_format: {type: json_object}` | 通过 | 未验证 |
| `anthropic_messages` | `POST` 完整 Messages URL；解析 `content` 中唯一 text block | `x-api-key` 和 `anthropic-version: 2023-06-01` | `output_config.format` JSON Schema | 通过 | 未验证 |
| `openai_responses` | `POST` 完整 Responses URL；聚合 `output[].content[]` 的 `output_text` | `Authorization: Bearer` | `text.format` strict JSON Schema | 通过 | 未验证 |
| `google_gemini` | `POST` 完整 `generateContent` URL；解析首个 candidate 的非 thought text parts | `x-goog-api-key` | `generationConfig.responseMimeType: application/json` 与 `responseSchema` | 通过 | 未验证 |

```sh
export BOTFABRIC_CLASSIFIER_REAL_LLM_FORMAT='anthropic_messages' # 可选；省略时为 openai_chat_completions
export BOTFABRIC_CLASSIFIER_REAL_LLM_ENDPOINT='https://api.example/v1/messages' # 对应所选 API 的完整 endpoint
export BOTFABRIC_CLASSIFIER_REAL_LLM_MODEL='your-model'
export BOTFABRIC_CLASSIFIER_REAL_LLM_API_KEY='由密钥管理器注入'
```

API Key 只通过协议要求的认证头发送，不得写入 manifest、日志或版本控制。生产环境使用 HTTPS；只允许 loopback HTTP 做本地测试。URL 不得包含凭据、query 或 fragment，HTTP 重定向不会跟随。分类输入只包含 topic、schema、群消息文本和候选应用 ID，不包含 headers、群号、用户号或原始 payload。分类器限制事件输入、候选数量与大小、总请求体及模型响应大小，并遵循 Router deadline。所有协议最终都须返回包含 `dispatch_mode` 和 `targets` 的 JSON；selective targets 必须是候选集的非空唯一子集。请求失败、解析错误或计划无效均由 Router 广播回退。

上述四种是协议适配，不代表任意给定服务或模型都支持所需 JSON 输出模式；第三方兼容性须在目标 endpoint/model 上单独确认。本地 stub 测试只验证请求和响应字段映射，不证明远端互操作性。

#### 基于固定数据集的路由质量评估

这里的“固定数据集”是指样本以 JSONL 文件保存，并不表示评估过程离线运行；命令会逐样本请求配置的模型服务并可能产生费用。

```json
{"input":"/help","candidates":["help","chat"],"expected":{"mode":"selective","targets":["help"]}}
```

运行评估时须带显式确认参数：

```sh
go run ./cmd/classifier-eval --input ./classifier-eval.jsonl --confirm-live-requests
```

程序输出 JSON：样本总数、完全匹配准确率、dispatch mode 准确率、目标 precision/recall 和失败数。失败计入总样本分母；准确率仅反映指定数据集与当次模型输出，不构成线上质量保证。
去重支持：

- `message_id`：优先使用协议消息 ID；
- `fingerprint`：群号、用户号和规范化文本；
- `auto`：有消息 ID 用消息 ID，否则用指纹；
- `drop` 或 `forward`；
- `Store` 接口提供进程内存与 Redis 两种实现；启用 Redis 时去重状态跨实例共享，`SET NX EX` 原子首占、TTL 自动过期；未启用时回退内存。

## 5. CandidateReply 与响应仲裁

应用端不应直接调用协议动作服务完成竞争回复，而应提交：

```go
type CandidateReply struct {
    EventID, ApplicationID string
    GroupID, Text          string
    TargetBotID            string
    Priority               int
    IdempotencyKey         string
}
```

调用 `botfabric.response/Submit` 后：

- `first_wins`：第一个有效候选原子获胜并发送，迟到候选丢弃；
- `priority_override`：在配置窗口内收集候选，窗口结束选择最高优先级；
- `RequiredReplyBot`：应用端不感知具体连接，中间层按 BotID 找协议端；
- `FallbackBots`：目标机器人不可用时按顺序选择备用机器人；
- 每事件最多一个 winner，幂等键避免重复发送。

响应状态存储与去重一样支持进程内存与 Redis 两种实现。Redis 实现以事件级 hash key + Lua 脚本保证 Claim/TryWin 原子，并以 key TTL 兜底进程崩溃；多实例共享后 winner 判定跨实例一致。

分布式 Store 配置（`config/runtime.example.yaml`）：

```yaml
redis:
  enabled: false # 关闭时去重与响应状态回退到进程内内存实现
  address: 127.0.0.1:6379
  password: ""
  db: 0
  key_prefix: "botfabric:" # 多实例共享 Redis 时的命名空间隔离
```

`enabled: true` 时装配路径在 `cmd/server/main.go`：连接 Redis（Ping 探活，不可用即启动失败）、创建去重与响应两个 Redis store、分别注入 `manager.SetDedupStore` 与 `coordinator.SetStore`。`key_prefix` 用于多实例共享同一 Redis 时的命名空间隔离，空值缺省为 `botfabric:`。Redis 不可用时本轮不自动降级内存——启用即要求可用，`Claim`/`TryWin` 在 Redis 出错时保守返回 false（视为已占用/已有 winner），避免重复发送。

## 6. OneBot 接入

### 6.1 协议端

`plugins/protocol/onebot` 作为 OneBot v11/v12 反向 WebSocket 服务端。协议端主动连接 BotFabric，事件转换为标准 `GroupMessage`，动作请求按 `BotID/EndpointID` 选择协议连接。

### 6.2 应用端

`internal/onebotapp` 支持三种模式：

- `server`：BotFabric 监听，应用端主动连接；
- `client`：BotFabric 主动连接应用端；
- `both`：两种方向同时启用。

应用端接收到 v11/v12 群消息事件后，可回发 `send_group_msg` 或 `send_message`。必须用 `__botfabric_event_id` 或 echo 关联原事件，适配器才会生成 CandidateReply。回复缺关联信息时，适配器按该连接同群最近一个未决事件 fallback 关联（仅按 `group_id` 过滤），使无法携带关联信息的简易应用端也能参与响应仲裁；无可用未决事件时回复失败（应用端收到 `failed`），不静默丢弃。

连接治理：

- **心跳保活**：`heartbeat_interval` > 0 时，中间层周期性发送 Ping 并以 Pong 续期读 deadline；无流量的死连接会在约 `2×heartbeat_interval` 后被检测并断开。`= 0` 保持无心跳行为（向后兼容，不推荐生产使用）。应用端实现需在读循环中处理 Ping 并回 Pong（OneBot 实现通常已具备）。
- **写超时**：`write_timeout` 作用于数据帧写，避免慢/卡死对端无限阻塞写锁。
- **client 重连**：`reconnect_interval` > 0 时，client/both 模式断线后按指数退避自动重连（上限 `reconnect_max_interval`，次数 `reconnect_max_tries`，0 表示无限）。`= 0` 保持旧行为（首次拨号失败即返回，不重连）。
- **server 身份保持**：应用端可在任一帧携带 `__botfabric_endpoint_id`（或 `self_id`）声明稳定身份；重连后以同 ID 复用端点，路由与响应状态可关联。未声明时退化为每次连接生成新 ID。
- **静默丢失修复**：事件被路由到无可用连接的应用端 sink 时，适配器返回错误使 EventBus 记死信，而非静默丢弃。

配置示例：

```yaml
application_onebot:
  enabled: true
  mode: both
  listen_address: 127.0.0.1:8091
  path_v11: /application/v11
  path_v12: /application/v12
  access_token: replace-me
  read_timeout: 10s
  write_timeout: 5s
  heartbeat_interval: 30s
  remote_address: 127.0.0.1:8092
  remote_path: /onebot
  remote_version: v11
  reconnect_interval: 2s
  reconnect_max_interval: 16s
  reconnect_max_tries: 0
```

## 7. Go SDK 与外部语言

Go 插件使用 `sdk/go`，只依赖 `pkg/contract`。SDK 提供 EventBus、ServiceGateway、JSON 编解码和超时辅助。

外部进程插件通过 Runtime 托管的 Unix Socket 双向 gRPC Session 接入。

外部进程插件可在 `limits` 下显式设置 `private_network: true`、`no_new_privileges: true`、`private_tmp: true`、`restrict_syscalls: true`、`restrict_address_families: true` 和/或 `capability_bounding_set`。Linux Runtime 会通过 systemd transient service 分别设置 `PrivateNetwork=yes`、`NoNewPrivileges=yes`、`PrivateTmp=yes`、固定 `SystemCallFilter=` 拒绝组、固定 `RestrictAddressFamilies=AF_UNIX` 和 `CapabilityBoundingSet=`；每项能力独立 opt-in。`capability_bounding_set` 是 `CAP_*` 名称列表，只允许所列 capability 留在进程 bounding set 中；显式空列表 `[]` 表示清空 bounding set，省略则维持 systemd 默认值。用户级 systemd manager 只有在内核启用非特权 user namespace、且 systemd 能建立相应 capability 限制时才可应用该属性；宿主拒绝或启动失败时 Runtime 会拒绝插件启动，不会无隔离降级。`no_new_privileges` 阻止插件及其后代通过 setuid/setgid/setcap exec 获得新增特权，但不会撤销已有权限，也不限制系统调用或网络。`private_tmp` 为插件提供独立的 `/tmp` 和 `/var/tmp` 视图。`restrict_syscalls` 使用固定拒绝组，`restrict_address_families` 使用固定值 `AF_UNIX`，两者都不支持在 Manifest 中自定义系统调用、地址族或 systemd 参数。若请求的属性因 systemd user manager、内核能力或权限不可用，Runtime 会拒绝启动，不会无隔离降级。启用 `private_tmp` 时，Runtime 的 Unix Socket 目录必须位于 `/tmp` 和 `/var/tmp` 之外，受影响的路径会在启动前被拒绝。未声明时维持原有行为；非 Linux 平台拒绝加载这些设置。

```yaml
runtime: process
limits:
  timeout: 5s
  memory: 256MiB
  private_network: true
  no_new_privileges: true
  private_tmp: true
  restrict_syscalls: true
  restrict_address_families: true
  capability_bounding_set: [CAP_NET_BIND_SERVICE]
```

`PrivateNetwork` 隔离宿主网络接口和宿主 loopback，插件自身 loopback 仍存在，不提供细粒度出站 allowlist。插件所需的宿主服务可经单独设计的代理暴露。`restrict_address_families` 只允许插件创建 Unix 域套接字，阻断 TCP/UDP 等网络地址族；它是粗粒度的地址族限制，不能按域名/IP 放行个别目标，也不替代 `private_network`，需要自行发起网络连接的插件不适用。`NoNewPrivileges` 不等同 seccomp，也不建立 capability 白名单；`capability_bounding_set` 限制通过 exec 获得 capability 的上界，不会撤销进程已拥有的 capability，且不是独立 UID 或完整权限隔离。`PrivateTmp` 隔离插件的 `/tmp` 与 `/var/tmp` 目录视图，但不构成完整文件系统沙箱。`restrict_syscalls` 通过 systemd `SystemCallFilter=` 拒绝固定系统调用类别，过滤范围不是 syscall allowlist，也不意味着其他 syscall 都安全。当前不支持域名/IP allowlist 或网络策略自动生成。

Runtime 以 `BOTFABRIC_SOCKET`、`BOTFABRIC_PLUGIN_ID`、`BOTFABRIC_PLUGIN_VERSION`、`BOTFABRIC_PROTOCOL_VERSION` 和随机 `BOTFABRIC_SESSION_TOKEN` 环境变量启动 `runtime: process` 的 `entry`，子进程首帧必须以这些身份信息完成握手；握手成功后，同一连接复用事件投递、服务调用、Health 与 Shutdown。`Provides.Services` 自动映射为 Runtime 到插件的远程服务，`Provides.Subscriptions` 自动映射为事件投递；插件向 Host 发布事件或调用服务时仍受 Manifest 和静态权限策略约束。协议生成代码位于 `gen/botfabric/v1`，跨语言 SDK 应以 `proto/botfabric/v1/process.proto` 为稳定契约。Go SDK 位于 `sdk/go`；Python 异步 SDK 位于 `sdk/python`，TypeScript/Node.js SDK 位于 `sdk/typescript`，安装和示例分别见对应 SDK README。

## 9. 当前限制

1. Go 核心路由默认广播；可选分类器失败时也回退广播；
2. 真实分类器支持 OpenAI Chat Completions、Anthropic Messages、OpenAI Responses 和 Google Gemini `generateContent` 四种 API 协议适配；还需在目标模型数据集上运行评估，兼容性依赖目标 endpoint 的协议和 JSON 输出能力；
3. 去重/响应 Store 支持进程内存与 Redis 共享两种实现；Redis 不可用时本轮不自动降级内存；
4. 应用端回复缺关联信息时按同群最近未决事件 fallback 关联，无未决事件时失败；建议应用端尽量显式携带 `__botfabric_event_id`/echo；
5. server 模式端点身份保持依赖应用端主动声明 `__botfabric_endpoint_id`/`self_id`，未声明时重连得新 ID；
6. Go/Python/TypeScript SDK 覆盖外部进程 Session；Linux 提供 opt-in 的 PrivateNetwork、NoNewPrivileges、PrivateTmp、固定 syscall 拒绝组、地址族限制（`AF_UNIX`）与 capability bounding set；PrivateTmp 启用时 Unix Socket 目录须在 `/tmp`、`/var/tmp` 外；capability bounding set 在 user systemd manager 上的实际生效依赖宿主 user namespace 能力；细粒度 egress 策略及其他平台等价隔离仍待后续。Router.Plan 已有默认广播与规则匹配的 Go 性能基准，内存 Deduplicator.Check 已有消息 ID 与文本指纹新事件路径基准；运行命令分别为 `go test ./internal/routing -run '^$' -bench '^BenchmarkRouterPlan' -benchmem` 和 `go test ./internal/dedup -run '^$' -bench '^BenchmarkDeduplicatorCheck' -benchmem`。两者用于本机比较，不代表跨环境性能承诺。
