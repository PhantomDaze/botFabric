# 生产部署指南

**适用对象**：准备把 BotFabric 部署到生产环境的运维与开发人员  
**基线**：Go 1.27；Linux 为完整能力平台（外部进程插件隔离依赖 Linux + systemd user manager）

本文只描述部署、配置与运维。接入协议端/应用端和开发插件见 [05-使用与接入.md](05-使用与接入.md)。

## 1. 部署拓扑与端口

单个 BotFabric 实例可以同时承担协议端接入、应用端接入、管理 API 和指标端点：

| 功能 | 默认示例地址 | 协议 | 认证 |
|------|--------------|------|------|
| OneBot 协议端（反向 WebSocket） | `127.0.0.1:8090` | HTTP/WebSocket | `onebot.access_token`（≥8 字符） |
| 应用端 OneBot 服务端 | `127.0.0.1:8091` | HTTP/WebSocket | `application_onebot.access_token`（≥8 字符） |
| 管理 API | `127.0.0.1:9090` | HTTP | Bearer Token（≥16 字符） |
| Prometheus 指标 | `127.0.0.1:9091` | HTTP | 无 |

生产环境建议只把协议端端口暴露给协议端所在的网络，其余端口仅绑定回环或内网。

## 2. 部署前检查

- [ ] 目标机器可运行 Go 1.27 构建的二进制（或已在 CI 完成构建）。
- [ ] 已确定配置、策略、插件目录、Unix Socket 目录的绝对路径与属主。
- [ ] 外部进程插件需要隔离时，确认宿主满足第 7 节要求（systemd user manager、linger、XDG_RUNTIME_DIR）。
- [ ] 需要多实例共享去重/响应状态时，已准备 Redis 并规划 `key_prefix`。
- [ ] 计划好 OneBot access token、管理 Bearer Token 的生成与轮换方式。
- [ ] 监控侧已准备抓取 `/metrics`，并接受“进程内累计、重启归零、多实例抓取侧聚合”的语义。

## 3. 构建

```bash
cd /opt/DEV/bot
go build -trimpath -ldflags="-s -w" -o build/botfabric ./cmd/server
```

交叉编译示例：

```bash
GOOS=linux GOARCH=amd64 go build -trimpath -ldflags="-s -w" -o build/botfabric-linux-amd64 ./cmd/server
```

发布前建议执行：

```bash
go vet ./...
go test ./...
go test -race ./...
```

## 4. 目录与权限

推荐的部署布局：

```text
/opt/botfabric/
├── bin/botfabric                 # 运行二进制（0755，root:root）
├── config/runtime.yaml           # 运行时配置（0600，botfabric:botfabric）
├── config/policy.yaml            # 权限策略（0600）
├── config/plugins/*.yaml         # 插件 Manifest（0644，只读）
└── run/                          # Unix Socket 目录（0700，botfabric:botfabric）
```

约定：

- `runtime.plugin_directory` 指向插件 Manifest 目录；Manifest 中 `runtime: process` 的 `entry` 建议写**绝对路径**，并直接 `exec` 目标程序。
- `transport.unix_socket_directory` 必须由服务用户可写，且**不要**放在 `/home`、`/root`、`/run/user` 下（会与 `protect_home` 冲突），也不要放在 `/tmp`、`/var/tmp` 下（会与 `private_tmp` 冲突）。
- 含密钥的配置文件权限设为 `0600`。BotFabric 不会把密钥写入日志，但插件只继承最小环境白名单（见第 9 节）。

## 5. 配置参考

运行时配置使用严格 YAML：未知字段、重复文档、无效时长/字节单位都会导致启动失败。

```yaml
runtime:
  plugin_directory: /opt/botfabric/config/plugins
  shutdown_timeout: 30s
  default_handler_timeout: 5s
  bot_id: bot-1
transport:
  unix_socket_directory: /opt/botfabric/run
  max_message_size: 4MiB
policy:
  file: /opt/botfabric/config/policy.yaml
  default: deny
observability:
  log_format: json
  metrics_enabled: true
  metrics_listen_address: 127.0.0.1:9091
  tracing_enabled: false
onebot:
  enabled: true
  listen_address: 127.0.0.1:8090
  path_v11: /onebot/v11
  path_v12: /onebot/v12
  access_token: <至少 8 字符>
  connect_timeout: 10s
  heartbeat_interval: 30s
  max_message_size: 4MiB
  write_timeout: 5s
application_onebot:
  enabled: true
  mode: both
  listen_address: 127.0.0.1:8091
  path_v11: /application/v11
  path_v12: /application/v12
  access_token: <至少 8 字符>
  read_timeout: 10s
  write_timeout: 5s
  heartbeat_interval: 30s
  remote_address: 127.0.0.1:8092
  remote_path: /onebot
  remote_version: v11
  reconnect_interval: 2s
  reconnect_max_interval: 16s
  reconnect_max_tries: 0
  max_message_size: 4MiB
redis:
  enabled: false
  address: 127.0.0.1:6379
  password: ""
  db: 0
  key_prefix: "botfabric:"
management:
  enabled: true
  listen_address: 127.0.0.1:9090
  bearer_token: <至少 16 字符>
```

字段约束：

| 字段 | 约束 |
|------|------|
| `runtime.plugin_directory` | 必填 |
| `runtime.shutdown_timeout` | `> 0`；systemd 的 `TimeoutStopSec` 应大于该值 |
| `runtime.default_handler_timeout` | `> 0` |
| `runtime.bot_id` | 非空 |
| `transport.unix_socket_directory` | 必填 |
| `transport.max_message_size` | `> 0`，支持 `B/KiB/MiB/GiB` |
| `policy.file` / `policy.default` | 必填；`deny` 或 `allow`，且必须与策略文件中的 `default` 一致 |
| `observability.log_format` | `json` 或 `text` |
| `observability.metrics_listen_address` | `metrics_enabled: true` 时必填 |
| `observability.tracing_enabled` | 保留字段，当前不导出外部追踪 |
| `onebot.*` | 启用时地址/路径必填，v11/v12 路径不能相同，token ≥8，`connect_timeout/heartbeat_interval/max_message_size > 0` |
| `application_onebot.mode` | `server` / `client` / `both`；留空按 `server` |
| `application_onebot.server 字段` | `listen_address`、两条路径必填且不同 |
| `application_onebot.client 字段` | `remote_address`、`remote_path` 必填，`remote_version` 为 `v11`/`v12` |
| `application_onebot.access_token` | ≥8 字符 |
| `application_onebot.read_timeout/write_timeout` | `> 0` |
| `application_onebot.max_message_size` | 省略或 `0` 取默认 4 MiB，上限 64 MiB |
| `redis.address` | 启用时必填；`db >= 0` |
| `management.bearer_token` | 启用时 ≥16 字符 |

**时长字段注意**：`Duration` 解析器拒绝 `<= 0` 的显式值。需要表示“禁用/无限”的字段（`application_onebot.heartbeat_interval`、`reconnect_interval`、`reconnect_max_interval`、`onebot.write_timeout`）应**省略字段**而不是写 `0s`，否则配置加载失败。

## 6. 权限策略

默认策略为 `deny`。生产上按最小权限逐项授予。应用端适配器使用固定内部主体 `application.onebot` 调用动作服务，必须在策略中显式授权：

```yaml
default: deny
plugins:
  protocol.onebot:
    publish: [bot.message.group]
    subscribe: []
    invoke: []
    provide: [protocol.qq.action]

  application.onebot:
    publish: []
    subscribe: []
    invoke:
      - service: protocol.qq.action
        methods: [SendMessage]
    provide: []

  example.reply:
    publish: []
    subscribe: [bot.message.group]
    invoke:
      - service: botfabric.response
        methods: [Submit, Cancel]
      - service: protocol.qq.action
        methods: [SendMessage]
    provide: []
```

`runtime.policy.default` 与策略文件 `default` 不一致时，启动直接失败。

## 7. systemd 部署

### 7.1 推荐：系统级服务 + 专用用户 + lingering

外部进程插件的沙箱通过 `systemd-run --user` 启动 transient service（cgroup v2 内存限制、PrivateNetwork、NoNewPrivileges、PrivateTmp、ProtectHome、ProtectSystem、syscall 过滤、地址族限制、capability bounding set）。要让服务用户拥有可用的 user systemd manager：

```bash
sudo useradd --system --home /opt/botfabric --shell /usr/sbin/nologin botfabric
sudo loginctl enable-linger botfabric
id -u botfabric        # 假设输出 1001，用于设置 XDG_RUNTIME_DIR
sudo install -d -o botfabric -g botfabric -m 0700 /opt/botfabric/run
```

`/etc/systemd/system/botfabric.service`：

```ini
[Unit]
Description=BotFabric runtime
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=botfabric
Group=botfabric
WorkingDirectory=/opt/botfabric
Environment=XDG_RUNTIME_DIR=/run/user/1001
ExecStart=/opt/botfabric/bin/botfabric /opt/botfabric/config/runtime.yaml
Restart=on-failure
RestartSec=3
KillSignal=SIGTERM
TimeoutStopSec=45
LimitNOFILE=65536

# 运行时自身的最小权限基线
NoNewPrivileges=yes
ProtectSystem=full
ProtectHome=yes
PrivateTmp=yes
ReadWritePaths=/opt/botfabric/run
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now botfabric
sudo systemctl status botfabric
```

说明：

- BotFabric 收到 `SIGTERM`/`SIGINT` 后按 `runtime.shutdown_timeout` 先停应用端 sink，再停插件；`TimeoutStopSec` 必须大于该值。
- 如果不需要外部进程隔离，可以省略 `XDG_RUNTIME_DIR` 与 lingering；此时内存限制失败会回退到 RSS 监控，但任何显式隔离请求仍会拒绝启动（不会静默降级）。
- `ProtectHome=yes` 只作用于 BotFabric 自身；插件侧的 `protect_home` 还会隐藏 `/home`、`/root`、`/run/user`，因此 Socket 目录与插件入口不要放在这些路径下。

### 7.2 备选：用户级服务

如果整套运行环境都归同一个登录用户管理，也可以使用 `systemctl --user`，此时 `systemd-run --user` 天然可用：

```ini
# ~/.config/systemd/user/botfabric.service
[Unit]
Description=BotFabric runtime
After=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/botfabric
ExecStart=/opt/botfabric/bin/botfabric /opt/botfabric/config/runtime.yaml
Restart=on-failure
KillSignal=SIGTERM
TimeoutStopSec=45

[Install]
WantedBy=default.target
```

```bash
systemctl --user daemon-reload
systemctl --user enable --now botfabric
loginctl enable-linger "$USER"
```

## 8. 容器部署注意

容器内通常没有可用的 systemd user manager，因此：

- `limits.memory` 无法通过 cgroup v2 transient service 生效，会回退为 RSS 监控；
- 任何显式隔离项（`private_network`、`no_new_privileges`、`private_tmp`、`protect_home`、`protect_system`、`restrict_syscalls`、`restrict_address_families`、`capability_bounding_set`）都会因 `systemd-run` 不可用而**拒绝启动**。

如果坚持容器部署，应在容器层提供等价隔离，并让插件 Manifest 不声明这些隔离项。同时：

- 挂载插件目录与 Socket 目录时确保用户可写；
- 把配置中的监听地址改为容器内地址，并通过端口映射限制外部访问；
- 管理 API 与 `/metrics` 不要直接暴露到公网。

## 9. 安全清单

- [ ] `policy.default: deny`，只授予插件实际需要的 publish/subscribe/invoke/provide。
- [ ] OneBot access token、应用端 token、管理 Bearer Token 均为随机值并定期轮换；不要复用。
- [ ] 管理 API 与 `/metrics` 仅绑定回环/内网；`/metrics` 无内置认证。
- [ ] 配置、策略、token 文件权限 `0600`；Socket 目录 `0700`。
- [ ] 外部进程插件 `entry` 使用绝对路径并直接 `exec`。BotFabric 用 `SO_PEERCRED` 将连接绑定到启动 PID，fork 子进程再连接的包装脚本会被拒绝。
- [ ] 外部插件只继承最小环境白名单（`PATH/HOME/USER/LOGNAME/TMPDIR/TZ/SHELL/LANG/LC_ALL/LC_CTYPE/TERM` + `BOTFABRIC_*`）。库路径、代理、Python 路径等需要在插件入口脚本内自行设置。
- [ ] 对不可信插件启用至少 `no_new_privileges`；需要网络隔离时用 `private_network`，需要文件系统限制时组合 `protect_home`、`protect_system`、`private_tmp`、`restrict_address_families`。
- [ ] 明确当前没有细粒度 egress allowlist；需要访问宿主服务时通过代理或单独设计的接口暴露。
- [ ] 多实例共享 Redis 时，Redis 只在内网可达，并设置密码与独立 `key_prefix`。

## 10. 可观测性

开启 `observability.metrics_enabled` 后，独立 HTTP 服务在 `/metrics` 输出 Prometheus 文本：

| 指标 | 含义 |
|------|------|
| `botfabric_events_published_total` | 通过鉴权并进入投递的事件数 |
| `botfabric_event_publish_denied_total` | 被权限策略拒绝的发布数 |
| `botfabric_duplicate_events_total{action}` | 去重命中数（按 drop/forward） |
| `botfabric_route_dropped_events_total` | 被路由规则丢弃的事件数 |
| `botfabric_dispatch_plans_total{mode}` | 投递计划数（按模式） |
| `botfabric_event_deliveries_total` / `botfabric_event_delivery_failures_total` | 投递成功/失败数 |
| `botfabric_dead_letters_total` | 进入死信的事件数 |
| `botfabric_classifier_fallbacks_total` | 分类器不可用导致的回退数 |
| `botfabric_response_candidates_total` / `accepted_total` / `discarded_total` | 候选回复提交/采纳/丢弃数 |
| `botfabric_plugin_start_failures_total` | 插件启动失败数 |

管理 API（Bearer Token）：

```bash
TOKEN='<management.bearer_token>'
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:9090/healthz
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:9090/v1/plugins
curl -s -H "Authorization: Bearer $TOKEN" 'http://127.0.0.1:9090/v1/dead-letters?offset=0&limit=100'
```

- `/healthz` 在任一插件不健康时返回 503。
- `/v1/dead-letters` 默认每页 100 条，硬上限 200。
- 指标为进程内累计值，重启归零；多实例需在抓取侧聚合。
- 日志为 JSON 或 text，TraceID 贯穿事件与日志；目前不导出外部 tracing 数据。

## 11. 多实例与 Redis

```yaml
redis:
  enabled: true
  address: 10.0.0.10:6379
  password: "<secret>"
  db: 0
  key_prefix: "botfabric:prod-a:"
```

- 启用后，去重与响应状态在实例间共享；key 由 `key_prefix` 隔离。
- Redis 连接失败会**直接导致启动失败**，运行中不会自动降级为内存实现。
- 指标仍是每实例本地计数，抓取侧按实例聚合。
- 端点注册、OneBot 连接、插件实例都是每实例本地的；多实例之间不做连接迁移或选主。

## 12. 容量与调优

| 项目 | 当前行为 |
|------|----------|
| 单条消息上限 | 协议端 `onebot.max_message_size`；应用端 `application_onebot.max_message_size`（默认 4 MiB，上限 64 MiB）；外部插件 transport `transport.max_message_size` |
| 应用端待回复事件 | 每连接 TTL 5 分钟、上限 1024 条（内部默认，当前不可配置）；写失败会回滚登记 |
| 内存去重 | 默认上限 65536 条，达到上限时淘汰最早过期键；高基数场景建议改用 Redis |
| 死信 | 默认 1024 条 / 8 MiB，载荷截断到 4 KiB、错误截断到 1 KiB；淘汰最旧记录 |
| 事件/服务超时 | `runtime.default_handler_timeout` 与插件 Manifest `limits.timeout` |
| 优雅关闭 | `runtime.shutdown_timeout`；systemd `TimeoutStopSec` 必须更大 |

## 13. 升级与回滚

1. 构建并校验新二进制（`go build ./... && go test ./...`）。
2. 备份当前二进制、配置、策略与插件 Manifest。
3. 替换二进制后 `systemctl restart botfabric`；服务会按 `shutdown_timeout` 优雅停止。
4. 检查 `/healthz`、`/v1/plugins`、`/metrics` 与日志。
5. 回滚：恢复上一版二进制与配置后重启。

注意事项：

- 配置变更需要重启，当前没有整体配置热加载；插件级 Reload 由 Runtime API 提供。
- 应用端稳定身份必须位于 `app:` 命名空间（如 `app:my-bot`）。旧部署若使用裸 `self_id` 或插件 ID，会被拒绝并退化为每连接新 ID，导致路由与响应关联失效。
- 外部插件环境已收窄为最小白名单；升级后若插件依赖 `LD_LIBRARY_PATH`、`PYTHONPATH`、代理变量等，需要在入口脚本中显式设置。
- 使用 `protect_home` 时确认 Socket 目录与插件入口不在 `/home`、`/root`、`/run/user` 下。

## 14. 故障排查

| 现象 | 常见原因 | 处理 |
|------|----------|------|
| 启动报 `metrics_listen_address` 为空 | 开启指标但未配置地址 | 配置 `observability.metrics_listen_address` |
| 启动报 `management.bearer_token` 长度不足 | token < 16 | 使用至少 16 字符的随机 token |
| 配置加载报“时长必须大于零” | 显式写了 `0s` | 省略该字段表示 0/禁用 |
| 启动报找不到 `systemd-run` / transient service 失败 | 无 user systemd manager 或未 linger | `loginctl enable-linger <user>`，设置正确的 `XDG_RUNTIME_DIR`；或移除隔离项并接受容器层隔离 |
| 插件启动被拒绝，提示 Socket 目录位于受保护路径 | `protect_home`/`private_tmp` 与目录位置冲突 | 把 `transport.unix_socket_directory` 移到 `/opt` 或 `/var/lib` 下 |
| 插件握手被拒绝 | 入口脚本 fork 子进程连接，`SO_PEERCRED` PID 不匹配 | 入口直接 `exec` 插件进程 |
| 插件找不到库/模块/代理 | 最小环境白名单未包含宿主变量 | 在入口脚本中 export 所需变量 |
| 应用端重连后路由关联失效 | 未声明稳定身份或未使用 `app:` 前缀 | 发送 `__botfabric_endpoint_id: app:<id>`（或 `self_id`） |
| 应用端回复返回 `failed` | 缺少 `echo`/`__botfabric_event_id`，且同群无未决事件 | 回复时携带原事件关联信息 |
| Redis 连接失败后进程退出 | Redis 不可用且未降级 | 恢复 Redis 或关闭 `redis.enabled` 后重启 |
| 大量重复消息 | 多协议端未启用去重或窗口过短 | 在 Manifest 中配置 `routing.dedup` 并评估 `window` |
| 慢客户端导致投递阻塞 | 对端读得太慢 | 检查应用端/协议端实现；必要时调大 `write_timeout` 并排查对端 |

## 15. 上线验收清单

```bash
# 构建与静态检查
go build ./...
go vet ./...

# 测试（发布流水线建议同时跑 -race）
go test ./...
go test -race ./...

# 启动后
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:9090/healthz
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:9090/v1/plugins
curl -s http://127.0.0.1:9091/metrics | head
```

- [ ] 所有插件状态为 healthy。
- [ ] 协议端连接与心跳正常，断线可重连。
- [ ] 应用端 server/client 模式与事件/回复往返正常。
- [ ] 路由规则、去重与响应仲裁按预期生效。
- [ ] 管理 API 与指标仅在内网/回环可达。
- [ ] 执行一次 `systemctl restart`，确认优雅关闭与恢复。
- [ ] 外部进程插件异常退出后，Runtime 将插件置为 failed 并回滚资源，日志可定位。
