# 架构设计

**版本**：3.0.0 | **状态**：核心运行时与路由仲裁已可运行 | **更新**：2026-08-25

## 核心定位

BotFabric 是位于协议端和应用端之间的完全插件化机器人中间层，支持不限数量的协议端与不限数量的应用端组成 N:N 拓扑。协议端和应用端可以通过 OneBot v11/v12 接入，也可以通过 BotFabric SDK/插件协议接入。

核心运行时不占有具体 QQ 业务，提供的是治理基础设施：插件生命周期、端点注册、标准事件、默认广播、可配置路由、跨协议端去重、响应仲裁、服务调用、权限、超时、健康检查和可观测性。

## 1. N:N 分层架构

```text
协议端 1..N ── OneBot v11/v12 ──┐
                                ▼
┌─────────────────────────────────────────────┐
│ BotFabric                                   │
│ 端点注册 │ 标准事件 │ 去重 │ 路由 │ 仲裁      │
│ EventBus │ ServiceGateway │ 权限 │ 生命周期   │
└─────────────────────────────────────────────┘
                                ▲
应用端 1..N ── OneBot 或 SDK/插件 ─┘
```

应用端与协议端不做一对一绑定。默认事件广播给所有匹配订阅者；路由规则可以选择部分应用端、丢弃事件或把事件发送给多个候选应用端。

## 2. 当前稳定契约

### 2.1 EventBus 与 ServiceGateway 分离

事件总线用于一对多、无同步返回的消息投递；服务网关用于一对一、有明确返回值的调用。当前实现不采用旧版统一 `CallGateway` 作为公共接口。

```go
type EventBus interface {
    Publish(ctx context.Context, event Event) error
    Subscribe(topic string, handler EventHandler, opts ...SubOption) (Subscription, error)
}

type ServiceGateway interface {
    Invoke(ctx context.Context, req Request) (Response, error)
    Register(service ServiceDescriptor, handler ServiceHandler) error
    Unregister(serviceID string) error
}
```

两者均由 Runtime 绑定可信插件身份，并执行权限、超时、活动状态和审计处理。

### 2.2 Endpoint

端点注册表区分协议端和应用端：

```go
type EndpointInfo struct {
    ID, Owner       string
    Kind            EndpointKind // protocol / application
    Protocol        string
    Version         string
    BotID           string
    ConnectionID    string
    Capabilities    []string
}
```

协议端连接在收到 self_id 后注册；应用端连接建立时注册。响应协调器按 `EndpointID`、`BotID` 和 fallback 选择目标协议端。

### 2.3 标准事件与消息

`Event` 包含 `BotID`、`EndpointID`、`RequiredReplyBot`、`ResponsePolicy` 等路由元数据；`GroupMessage` 和 `SendMessageRequest` 中的 QQ ID 使用字符串，避免大整数精度损失。

## 3. 事件处理链路

```text
协议端接入
  → 归一化 GroupMessage
  → EventBus.Publish
  → 可选 Deduplicator
  → Router.Plan
  → 应用端 EventSink / 进程内订阅者
  → CandidateReply
  → ResponseCoordinator
  → protocol.qq.action/SendMessage
  → 指定协议端连接
```

无去重器、无匹配规则时，行为就是原始默认广播。单个订阅者或 sink 失败会记录死信，不阻塞其他投递目标。

## 4. 路由规则

路由规则声明在插件 Manifest 的 `routing` 段，由 Runtime 按插件 owner 注册和卸载。规则支持：

- Topic、Schema、协议、版本、BotID、群号、用户号和 Header 匹配；
- 文本正则过滤；
- priority 优先级；
- broadcast、selective、drop；
- fallback 规则；
- 可选 RouteClassifier（当前提供 mock，真实 LLM 留作后续插件）。

示例：

```yaml
routing:
  rules:
    - id: command-help
      priority: 100
      match:
        topic: bot.message.group
        text_regex: '^/help(?:\s|$)'
      action:
        mode: selective
        targets: [example.reply]
```

默认无匹配规则为 broadcast。四个内置预设位于 `plugins/routing`：默认广播、正则选择、竞争响应、指定机器人回复。

## 5. 去重与竞争响应

### 5.1 协议端去重

`DedupSpec` 支持 `message_id`、`fingerprint`、`auto`。在配置窗口内，多个协议端收到同一消息时首个事件获得主事件资格；后续重复事件可以 drop，或以 `botfabric_duplicate=true` 标记后 forward。

去重存储使用 `Store` 接口，提供两种实现：

- 进程内内存 TTL 实现：单实例运行，无需外部依赖；
- Redis 共享实现：多实例运行时去重状态跨实例共享，`SET key NX EX` 原子首占，TTL 自动过期，无需周期清理。进程崩溃后 key 由 Redis TTL 兜底过期，不泄漏状态。

未启用 Redis 时回退内存实现；二者经同一接口替换，业务无感。

### 5.2 应用端竞争响应

应用端不直接调用协议动作，而提交：

```go
type CandidateReply struct {
    EventID, ApplicationID string
    GroupID, Text          string
    TargetBotID            string
    Priority               int
    IdempotencyKey         string
}
```

响应协调器支持：

- `first_wins`：第一个有效回复原子获胜并立即发送；
- `priority_override`：在时间窗口内收集候选，窗口结束后选择最高优先级；
- 幂等键和每事件单 winner；
- `RequiredReplyBot`：应用端无需识别协议端，中间层按 BotID/EndpointID 选择最终发送连接；
- `FallbackBots`：指定机器人不可用时按规则选择备用 Bot。

响应状态存储同样支持进程内内存与 Redis 两种实现。Redis 实现以每事件一个 hash key 表达状态，用 Lua 脚本保证 Claim/TryWin 原子性，并在每次状态变更时刷新 key TTL 作为进程崩溃时的兜底清理（内存实现依赖 `time.AfterFunc`，进程死亡时不触发，状态会泄漏）。多实例共享 Redis 后 winner 判定跨实例一致。

## 6. OneBot 接入

### 6.1 协议端

`plugins/protocol/onebot` 作为 OneBot v11/v12 反向 WebSocket 服务端，协议端主动连接 BotFabric。收到事件后归一化，动作调用根据 `SendMessageRequest.BotID/EndpointID` 选择协议端连接。

### 6.2 应用端

`internal/onebotapp` 同时支持：

- `server`：BotFabric 监听 WebSocket，应用端主动连接；
- `client`：BotFabric 主动连接应用端提供的 OneBot WebSocket 服务；
- `both`：同时启用两种方向。

应用端收到标准 OneBot v11/v12 事件后，可回发 `send_group_msg` 或 `send_message`。回复必须使用推送事件中的 `__botfabric_event_id` 或 echo 关联原事件，适配器会转换为 CandidateReply 并提交响应协调器。回复缺关联信息时，适配器按该连接同群最近一个未决事件 fallback 关联（仅按 `group_id` 过滤），使无法携带关联信息的简易应用端也能参与响应仲裁；无可用未决事件时回复失败，事件是否已被协调器过期释放由协调器兜底判定。

## 7. 插件与非 Go 兼容层

Go 插件使用 `pkg/contract` 与 `sdk/go`。外部进程插件的 Protobuf/Unix Socket 握手契约已经定义，但完整传输实现仍待后续切片。该边界为 Python、TypeScript、Rust 等语言 SDK 保留扩展点，不把非 Go 语言强耦合进核心。

## 8. 生命周期与安全

Runtime 支持发现、校验、启动、停止、卸载和原子重载。停止/卸载先拒绝新任务，再等待在途事件和服务调用，最后清理服务、订阅、端点、路由规则和分类器。

权限策略默认为 deny，覆盖发布、订阅、服务调用和服务提供。所有服务调用带 Caller、TraceID、超时和审计日志。管理 API 默认关闭，并使用 Bearer Token。

## 9. 当前限制

1. 外部进程传输仍是握手骨架；
2. LLM 只有接口和 mock 分类器；
3. 去重和响应状态支持进程内存与 Redis 共享两种实现；Redis 不可用时本轮不自动降级内存（启用即要求可用）；
4. 应用端 OneBot 的事件关联优先依赖 `__botfabric_event_id`/echo，缺关联时按同群最近未决事件 fallback；
5. Python/TypeScript SDK、高级沙箱和性能基准仍待后续切片。
