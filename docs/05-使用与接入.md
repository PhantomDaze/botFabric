# 使用与接入指南

**适用对象**：接入 OneBot 协议端/应用端、配置路由规则、开发插件的开发者  
**前置阅读**：[02-架构设计.md](02-架构设计.md)（模型与链路）、[03-开发指南.md](03-开发指南.md)（完整契约）

本文按“第一次接入”的顺序组织：先跑通最小示例，再分别接入协议端、应用端，最后配置路由、响应仲裁与插件。

## 1. 接入方式总览

| 角色 | 接入方式 | 适用场景 |
|------|----------|----------|
| 协议端 | OneBot v11/v12 反向 WebSocket | 把 QQ 协议实现（NapCat、Lagrange、LLOneBot 等）接到 BotFabric |
| 应用端 | OneBot v11/v12（server / client / both） | 已有的 OneBot 应用直接收发群消息 |
| 进程内插件 | Go 插件接口 + `pkg/contract` | 与运行时同进程、需要低延迟或直接访问运行时能力 |
| 外部进程插件 | Unix Socket 双向 gRPC | 需要独立进程、独立语言或沙箱隔离（Go/Python/TypeScript SDK） |

一个实例可以同时承担以上所有角色；协议端与应用端之间不做一对一绑定。

## 2. 最小可运行示例

```bash
go build -o bin/botfabric ./cmd/server
./bin/botfabric config/runtime.example.yaml
```

默认示例：

- `onebot.enabled: false`，加载 `protocol.mockonebot`，不连接真实 QQ；
- 加载 `example.reply`，收到群消息后提交候选回复 `收到：<原文>`；
- 管理 API 与指标默认关闭。

建议第一次启动时打开管理 API，便于确认插件状态：

```yaml
management:
  enabled: true
  listen_address: 127.0.0.1:9090
  bearer_token: local-dev-token-0123456789
```

```bash
curl -s -H "Authorization: Bearer local-dev-token-0123456789" http://127.0.0.1:9090/healthz
curl -s -H "Authorization: Bearer local-dev-token-0123456789" http://127.0.0.1:9090/v1/plugins
```

## 3. 协议端接入（OneBot v11/v12）

BotFabric 作为反向 WebSocket 服务端，协议端主动连接。

### 3.1 运行时配置

```yaml
onebot:
  enabled: true
  listen_address: 0.0.0.0:8090
  path_v11: /onebot/v11
  path_v12: /onebot/v12
  access_token: replace-with-at-least-8-chars
  connect_timeout: 10s
  heartbeat_interval: 30s
  max_message_size: 4MiB
  write_timeout: 5s
```

### 3.2 插件清单

插件目录中需要 `runtime: in_process`、`entry: builtin.onebot` 的清单（示例见 `config/plugins/onebot.yaml`）：

```yaml
id: protocol.onebot
name: OneBot v11/v12 Protocol
version: 0.1.0
runtime: in_process
entry: builtin.onebot
provides:
  services:
    - name: protocol.qq.action
      methods: [SendMessage]
  subscriptions: []
requires:
  services: []
  permissions: []
limits:
  timeout: 5s
```

### 3.3 协议端侧配置

- 反向 WebSocket 地址：`ws://<botfabric-host>:8090/onebot/v11` 或 `.../onebot/v12`；
- 请求头：`Authorization: Bearer <onebot.access_token>`；
- 连接建立并收到 `self_id` 后，BotFabric 注册协议端端点；
- 群消息被归一化为标准 `GroupMessage`，动作请求通过 `protocol.qq.action/SendMessage` 发送。

生产上建议把 8090 只暴露给协议端所在网络，并禁用 `protocol.mockonebot`（`onebot.enabled: true` 时运行时会自动跳过 mock 清单）。

## 4. 应用端接入（OneBot）

### 4.1 模式

| `application_onebot.mode` | 行为 |
|---------------------------|------|
| `server`（默认） | BotFabric 监听，应用端主动连接 |
| `client` | BotFabric 主动连接远端应用端 |
| `both` | 两种方向同时启用 |

### 4.2 server 模式

```yaml
application_onebot:
  enabled: true
  mode: server
  listen_address: 127.0.0.1:8091
  path_v11: /application/v11
  path_v12: /application/v12
  access_token: replace-with-at-least-8-chars
  read_timeout: 10s
  write_timeout: 5s
  heartbeat_interval: 30s
  max_message_size: 4MiB
```

应用端连接 `ws://<host>:8091/application/v11`（或 v12），携带 `Authorization: Bearer <token>`。

BotFabric 推送的事件保留 OneBot 风格，并额外携带 `__botfabric_event_id`：

```json
{
  "time": 1760000000,
  "self_id": "bot-1",
  "post_type": "message",
  "message_type": "group",
  "message_id": "m-1",
  "group_id": "123456789",
  "user_id": "42",
  "message": "/help",
  "raw_message": "/help",
  "__botfabric_event_id": "evt-1"
}
```

v12 事件使用 `type/detail_type/id/message` 字段，其中 `message` 是消息段数组：

```json
{
  "time": 1760000000,
  "type": "message",
  "detail_type": "group",
  "id": "m-1",
  "group_id": "123456789",
  "user_id": "42",
  "message": [{"type": "text", "data": {"text": "/help"}}],
  "alt_message": "/help",
  "__botfabric_event_id": "evt-1"
}
```

数字型 `group_id` 会按原始文本保留，不会因浮点格式化丢失精度。

### 4.3 client / both 模式

```yaml
application_onebot:
  enabled: true
  mode: both
  # ... server 字段 ...
  remote_address: 127.0.0.1:8092
  remote_path: /onebot
  remote_version: v11
  reconnect_interval: 2s
  reconnect_max_interval: 16s
  reconnect_max_tries: 0   # 0 表示无限重连
```

`reconnect_interval` 省略表示不自动重连（首次拨号失败即返回）。`remote_version` 必须是 `v11` 或 `v12`。

### 4.4 回复与事件关联

应用端可发送两种 action：

- `send_group_msg`：`params.group_id` + 字符串 `params.message`；
- `send_message`：`params.group_id` + v12 消息段数组 `params.message`。

回复必须关联原事件，二选一：

1. `params.__botfabric_event_id` 填推送事件中的 ID；
2. `echo` 字段回填同样的 ID。

```json
{
  "action": "send_group_msg",
  "params": {
    "group_id": "123456789",
    "message": "收到",
    "__botfabric_event_id": "evt-1"
  },
  "echo": "evt-1"
}
```

如果两者都缺失，适配器会按**同群最近一个未决事件**做 fallback 关联；没有可用未决事件时返回：

```json
{"status": "failed", "retcode": 1, "message": "应用端回复缺少有效的 event_id/echo 关联，且无可用的最近未决事件"}
```

显式关联始终优先，建议应用端尽量携带。成功时返回：

```json
{"status": "ok", "retcode": 0, "data": {"Accepted": true}, "echo": "evt-1"}
```

实际 `data` 内容由响应协调器返回，字段以运行时版本为准。

### 4.5 稳定身份

应用端可在任意帧携带 `__botfabric_endpoint_id` 或 `self_id` 声明稳定身份，重连后复用同一端点，路由与响应状态才能持续关联。

规则：

- 必须位于保留命名空间 `app:` 下，例如 `app:my-bot`；
- 空值、插件 ID、已被其他 owner 注册的 ID 一律拒绝；
- 未声明时每次连接生成新 ID（不推荐用于生产）。

```json
{"__botfabric_endpoint_id": "app:my-bot"}
```

纯身份声明帧（无 `action`）合法，会收到 `{"status":"ok","retcode":0}`。

### 4.6 连接治理

- `heartbeat_interval > 0`：中间层周期性 Ping，Pong 续期；无流量死连接约 `2×heartbeat_interval` 后断开。省略字段表示不心跳（仅为兼容旧行为，生产不推荐）。
- `write_timeout`：保护慢/卡死对端的写锁。
- `read_timeout`：读 deadline。
- `max_message_size`：单条读上限，默认 4 MiB，上限 64 MiB；超限断开连接。
- 事件无法投递（例如没有可用连接）时进入死信，而不是静默丢弃。

### 4.7 动作授权主体

应用端提交候选回复时，动作调用使用固定内部主体 `application.onebot`，不采用客户端可声明的端点 ID。默认 deny 策略下必须在策略文件中授权：

```yaml
plugins:
  application.onebot:
    publish: []
    subscribe: []
    invoke:
      - service: protocol.qq.action
        methods: [SendMessage]
    provide: []
```

## 5. 路由配置

路由规则写在插件 Manifest 的 `routing` 段，由 Runtime 装载：

```yaml
id: my.routing
name: My Routing
version: 0.1.0
runtime: in_process
entry: builtin.routing.preset.broadcast   # 任一同进程 entry 均可承载 RoutingSpec

routing:
  dedup:
    enabled: true
    strategy: auto          # message_id / fingerprint / auto
    window: 2s
    duplicate_mode: forward # drop / forward
  rules:
    - id: help
      priority: 100
      match:
        topic: bot.message.group
        text_regex: '^/help(?:\s|$)'
      action:
        mode: selective     # broadcast / selective / drop
        targets: [example.reply]
        response:
          mode: first_wins  # none / first_wins / priority_override
          timeout: 3s
```

### 5.1 匹配字段

| 字段 | 含义 |
|------|------|
| `topic` | 事件主题，如 `bot.message.group` |
| `schema` | 事件 schema |
| `protocol` / `version` | 来源协议与版本 |
| `bot_id` | 来源机器人 |
| `group_id` / `user_id` | 群号/用户号（字符串） |
| `text_regex` | 群消息文本正则（RE2） |
| `headers` | 事件头精确匹配 |

零值字段表示不约束。多条规则按 `priority` 从高到低匹配，命中第一条即执行。

### 5.2 常用示例

**只把 `/help` 交给某个应用**：

```yaml
- id: help
  priority: 100
  match: {topic: bot.message.group, text_regex: '^/help(?:\s|$)'}
  action: {mode: selective, targets: [example.reply]}
```

**丢弃某类消息**：

```yaml
- id: drop-noise
  priority: 200
  match: {topic: bot.message.group, text_regex: '^\s*$'}
  action: {mode: drop}
```

**默认广播兜底**（用 `fallback: true`，仅在无其他规则命中时使用）：

```yaml
- id: default
  priority: 0
  match: {topic: bot.message.group}
  action: {mode: broadcast, fallback: true}
```

**竞争回复（first-wins）**：

```yaml
- id: race
  priority: 100
  match: {topic: bot.message.group}
  action:
    mode: broadcast
    response: {mode: first_wins, timeout: 3s}
```

**指定机器人回复，失败时回退**：

```yaml
- id: required-bot
  priority: 100
  match: {topic: bot.message.group}
  action:
    mode: broadcast
    response:
      mode: first_wins
      timeout: 3s
      required_reply_bot: bot-b
      fallback_bots: [bot-a]
```

**交给分类器决定**：

```yaml
- id: classified
  priority: 100
  match: {topic: bot.message.group}
  action:
    mode: selective
    classifier: classifier.real-llm
```

分类器不可用、失败或返回无效计划时，Router 回退为对候选应用端广播，并累加 `botfabric_classifier_fallbacks_total`。

### 5.3 去重

```yaml
routing:
  dedup:
    enabled: true
    strategy: auto
    window: 2s
    duplicate_mode: forward
```

- `message_id`：按 `EndpointID + MessageID` 判定；
- `fingerprint`：按 `GroupID + UserID + 归一化文本 + 时间窗口` 判定；
- `auto`：有稳定 message_id 时用 message_id，否则用指纹；
- `drop`：重复事件不再投递；`forward`：仍投递但标记重复，适合“指定机器人代收”场景。

多实例共享去重结果需要启用 Redis（见 [04-生产部署.md](04-生产部署.md) 第 11 节）。

### 5.4 内置路由预设

`plugins/routing` 提供四个预设，使用对应 `entry` 的 Manifest 即可装载：

| 预设 | entry | 行为 |
|------|-------|------|
| broadcast | `builtin.routing.preset.broadcast` | 全广播 |
| regex | `builtin.routing.preset.regex` | `/help` 定向到 `example.reply` |
| competition | `builtin.routing.preset.competition` | 广播 + first-wins |
| required-bot | `builtin.routing.preset.required_bot` | 广播 + 指定 bot-b、回退 bot-a、auto 去重 forward |

预设是示例与起点，生产配置建议按实际应用 ID 改写。

## 6. 响应仲裁

应用端/插件提交 `CandidateReply`：

```json
{
  "event_id": "evt-1",
  "application_id": "example.reply",
  "group_id": "123456789",
  "text": "收到",
  "priority": 10,
  "idempotency_key": "optional-key"
}
```

| 模式 | 行为 |
|------|------|
| `none` | 不启用仲裁，应用端直接发送 |
| `first_wins` | 第一个有效回复立即发送，其余丢弃 |
| `priority_override` | 在 `timeout` 内收集候选，取最高 `priority` 的有效回复发送 |

- `idempotency_key` 相同的重复提交只采纳一次；
- `required_reply_bot` 把回复固定到目标机器人，目标不可用时按 `fallback_bots` 回退；
- 被丢弃的候选会累加 `botfabric_response_discarded_total`。

## 7. 权限策略

权限默认 deny。策略文件格式：

```yaml
default: deny
plugins:
  <plugin-id>:
    publish: [topic, ...]
    subscribe: [topic, ...]
    invoke:
      - service: <service-name>
        methods: [MethodA, MethodB]
    provide: [service-name, ...]
```

要点：

- `runtime.policy.default` 必须与策略文件 `default` 一致；
- 进程内插件按 Manifest ID 授权；外部进程插件同样按 Manifest ID；
- 应用端适配器固定使用 `application.onebot`；
- 服务调用方身份由 Runtime 绑定，不信任调用载荷中的自报身份。

## 8. 开发插件

### 8.1 进程内 Go 插件

进程内插件需要与 `cmd/server` 一起编译，并在 `plugins/builtin/register.go` 注册工厂（entry 字符串 → 构造函数）。插件实现 `contract.Plugin`：

```go
type Plugin interface {
    Manifest() Manifest
    Start(ctx context.Context, host Host) error
    Stop(ctx context.Context) error
    Health(ctx context.Context) HealthStatus
}
```

最小 Manifest：

```yaml
id: example.reply
name: Example Reply
version: 0.1.0
runtime: in_process
entry: builtin.reply
provides:
  subscriptions: [bot.message.group]
requires:
  services: [botfabric.response, protocol.qq.action]
  permissions: [event.read.message, action.send_message]
limits:
  timeout: 2s
```

完整事件/服务/端点契约与示例见 [03-开发指南.md](03-开发指南.md)。仓库中的 `plugins/application/reply` 是可运行的参考实现。

### 8.2 外部进程插件

Manifest 使用 `runtime: process`，`entry` 为可执行文件绝对路径：

```yaml
id: example.external
name: External Echo
version: 0.1.0
runtime: process
entry: /opt/botfabric/plugins/echo/run.sh
provides:
  services:
    - name: example.echo
      methods: [Run]
  subscriptions: [bot.message.group]
requires:
  services: []
  permissions: []
limits:
  timeout: 5s
  memory: 256MiB
  # 可选隔离（Linux + systemd user manager）
  no_new_privileges: true
  private_network: false
```

Runtime 注入以下环境变量并等待首帧握手：

```text
BOTFABRIC_SOCKET
BOTFABRIC_PLUGIN_ID
BOTFABRIC_PLUGIN_VERSION
BOTFABRIC_PROTOCOL_VERSION
BOTFABRIC_SESSION_TOKEN
```

插件进程只继承最小环境白名单，需要额外变量时在入口脚本中 export。SDK 会自动读取上述变量并完成握手：

- Go：`sdk/go`
- Python：`sdk/python`（`pip install ./sdk/python`）
- TypeScript/Node.js：`sdk/typescript`（Node.js 20+，`npm install ./sdk/typescript`）

Python 最小示例：

```python
from botfabric import SessionClient, Event

async def on_event(event: Event) -> None:
    print(event.topic, event.payload)

client = SessionClient(subscriptions={"bot.message.group": on_event})
await client.connect()
try:
    await client.serve_forever()
finally:
    await client.close()
```

TypeScript 最小示例：

```typescript
import { SessionClient, type Event } from "@botfabric/sdk";

const client = new SessionClient({
  subscriptions: {
    "bot.message.group": async (event: Event) => {
      console.log(event.topic);
    },
  },
});
await client.connect();
try {
  await client.serveForever();
} finally {
  await client.close();
}
```

隔离选项在宿主不支持时会导致插件**拒绝启动**，不会无隔离降级。各选项语义与限制见 [03-开发指南.md](03-开发指南.md) 第 7 节。

## 10. 常见问题

| 问题 | 处理 |
|------|------|
| 应用端回复返回 `failed` | 检查是否携带 `echo` 或 `params.__botfabric_event_id`；否则确认同群是否有未决事件 |
| 重连后响应关联失效 | 声明稳定身份 `app:<id>`，不要使用裸 `self_id`/插件 ID |
| 协议端连不上 | 检查反向 WS 地址、v11/v12 路径、`Authorization: Bearer` token 与监听地址 |
| 事件被丢弃 | 检查路由 `drop` 规则、`required_reply_bot` 目标是否在线、权限策略是否放行 |
| 多协议端重复回复 | 开启 `routing.dedup`，评估 `strategy` 与 `window` |
| 插件收不到事件 | 确认 Manifest `provides.subscriptions`、策略 `subscribe` 与路由 `targets` |
| 插件无法启动 | 查看日志中的隔离/systemd/peercred 错误，对应处理见 [04-生产部署.md](04-生产部署.md) 第 14 节 |
| 分类器请求失败 | Router 会回退广播；检查 endpoint、模型、密钥环境变量与网络 |
